Maintenance Command Cheat Sheet

The six commands that keep a library healthy, in the order you'd normally reach for them.

Primary source: commands/{init,status,lint,audit,repair-fulltext,maintain}.md — these spec files are authoritative; the scripts under skills/ref-manager/scripts/ are the ground truth when the docs are ambiguous. See Lesson 0002 for the narrative version.
CommandPurposeReadsWritesKey flags
/ref:init <path> Create the library skeleton. Run once per library. — log.md, top-level dirs, ~/.config/ref-manager/config.json —
/ref:status One-line health state + what to run next. The "glance" tool. Whole library (counts only) — (read-only) --verbosity quick|normal|verbose
/ref:lint Deep read-only sweep: missing metadata, abstract-only, OA-pending, missing claim registries, stale retraction checks, stale catalog. The "diagnose" tool. Whole library maintenance/<UTC-timestamp>.json (only with --snapshot) --stale-days N, --json, --snapshot, --diff [snapshot]
/ref:audit Re-check retraction/errata status against PubMed. --citations switches to recording dated PMC cited-by counts instead. No selector = whole library (unique among selector-taking commands). PubMed metadata (retraction mode) or NCBI ELink pmc_pmc_citedby (citations mode) papers/<pmid>/... retraction status; citations.json (append-only, never overwritten — D25) [selector], --citations, show-citations
/ref:repair-fulltext Batch-fix the metadata_only / abstract_only / oa_pending buckets lint found, by re-running the /ref:fetch acquisition workflow per PMID. The "fix" tool. Resume-safe across runs. lint.py --json output; repair_state.py read Full text via fetch.py; maintenance/repair-fulltext-state.json via repair_state.py merge (atomic, lock-protected) --limit N (default 20), --retry-failed, --stale-days N, [selector]
/ref:maintain Orchestration wrapper: runs status → lint (snapshotted) → index rebuild → audit, in one command, then prints concrete next steps. Does not replace any of the commands it wraps — each is still useful standalone. Same as the stages it runs Same as the stages it runs, plus a lint snapshot every time --stale-days N, --no-index, --no-audit, --verbosity quick|normal|verbose

The loop, in one line

/ref:status to glance → /ref:lint to diagnose → /ref:repair-fulltext and /ref:audit to fix → /ref:maintain to do all four in sequence when you don't need to inspect each stage separately.

Rules that don't show up in the flags

  • Nothing here ever silently overwrites a frozen artifact. If /ref:audit flips a paper's retraction status, any saved /ref:brief//ref:compare//ref:summarize that used it is flagged as potentially_stale_artifacts — refreshing it is a separate, explicit --refresh call.
  • /ref:repair-fulltext never invents success: a paper with no real OA full text legitimately stays abstract_only/oa_location_found across runs.
  • /ref:audit --citations counts are PMC-indexed citing articles only — an undercount of total literature citations, never presented as a total.
