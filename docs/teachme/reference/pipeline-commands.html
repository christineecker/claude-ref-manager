Pipeline Command Cheat Sheet

Init → add → fetch → extract, at a glance.

Primary source: commands/{init,add,fetch,extract}.md, agents/ref-extractor.md. See Lesson 0003 for the narrative version.
CommandRequiresDoesWritesResult lines
/ref:init <path> — Create library skeleton at <path>; record it as active. log.md, top-level dirs, ~/.config/ref-manager/config.json —
/ref:add <pmid...> Active library Batch-resolve PMIDs via PubMed metadata; normalize; commit. papers/<pmid>/{meta,authorship,funding}.json, raw/<sha256>/response.json added / already_present / failed (per PMID, independent)
/ref:fetch <pmid...> meta.json (from add) Try sources in priority order (below); convert + commit the first that works. raw/<new-sha256>/source.*, versions/<v-id>/{manifest,source.md,figures.json}, flips current.json acquired / duplicate_noop / oa_location_found / abstract_only / failed
/ref:extract <pmid...> Title + (full text or abstract) One ref-extractor subagent per PMID, in parallel; classify study type, normalize claims to PICO+. versions/<v-id>/{claims.json,claim_registry.json} extracted / failed (per PMID, independent)

/ref:fetch's source priority

  1. PMC JATS XML — needs a PMCID. Only path yielding figures.json. Tried first.
  2. PubMed full-text tool — fallback, pre-extracted plain text (structure lost).
  3. Unpaywall (by DOI) — finds a location, doesn't download; reports oa_location_found.
  4. Publisher HTML — fetched by the calling agent, handed in.
  5. None worked — abstract_only. Expected, not a failure.

Rules that don't show up in the flags

  • Every field a ref-extractor subagent can't determine is the literal string "unknown" — never omitted, never guessed.
  • Every claim carries a direct-quote evidence_span, not a paraphrase.
  • A re-extraction that changes a claim at the same locator supersedes it (new claim_id; old one kept with superseded_by) — nothing is deleted.
  • fetch's duplicate_noop mirrors the content-addressed raw/<sha256>/ pattern from Lesson 0001: identical source, no new version.
  • Every command here processes each PMID independently — one failure never blocks the batch.
  • fetch does not run add for you. A PMID with no meta.json fails that PMID with no meta.json -- run /ref:add first, checked before any source is tried.
