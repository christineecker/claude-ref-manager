Appraising evidence: risk of bias and GRADE

What /ref:review --batch does when it appraises a set of papers: which checklist each paper gets (RoB 2, Newcastle-Ottawa or AMSTAR-2), what every domain is actually based on, and how those ratings roll up into one GRADE certainty for the set. Every rule here is taken from appraise.py; the worked example is a real run against a scratch library.

The pipeline

Appraisal is entirely deterministic: no LLM reads the papers at this stage. It works from the claims /ref:extract already committed, so it can only rate what the claim schema records. The schema records PICO and effect data, not methods detail like blinding or allocation concealment, so expect many domains to say insufficient_information. That is the honest answer, not a failure.

Full text first

RoB 2, Newcastle-Ottawa, AMSTAR-2 and GRADE all need methods detail an abstract doesn't carry. So the tier gate runs before anything else:

  • No full-tier paper in the set: the review is refused and nothing is written.
  • Mixed set: full-tier papers are appraised; each abstract-tier paper is listed as insufficient_information, not dropped.

output from a scratch library

› /ref:review 99000203 --batch abstract-only
{
  "status": "refused",
  "batch": "abstract-only",
  "reason": "selected set is wholly abstract-tier -- appraisal needs full-text detail; not proceeding (§8 phase-10 gate)",
  "by_extraction_tier": { "abstract": 1, "full": 0, "unavailable": 0, "missing_record": 0 }
}

To fix a refusal, get full text with /ref:fetch or /ref:attach and re-extract.

Which checklist a paper gets

A paper's study type is the most common study_type among its active claims, set by the extractor. That picks exactly one checklist:

study_typeChecklistWhat it is
rctRoB 2Cochrane's risk-of-bias tool for randomised trials (Sterne et al., BMJ 2019). Five domains, each rated low / some concerns / high.
cohort, case_controlNewcastle-Ottawa (NOS)A star system for non-randomised studies (Wells et al.). Three categories: selection (up to 4 stars), comparability (2), outcome or exposure (3).
meta_analysisAMSTAR-2A tool for rating systematic reviews (Shea et al., BMJ 2017). 16 items, 7 of them critical, rolled up into an overall confidence.
anything elsenoneA note that no standard checklist applies. No rating is forced.

RoB 2: five domains

Each domain looks for one signal in the claims. Three domains can be rated from claim data; the other two are always insufficient_information.

DomainWhat the tool looks atPossible drafts
randomization_processhigh if study_design or evidence_span describes quasi-random or non-random allocation ("quasi-randomised", "not randomised", "allocated by date of birth", "alternate allocation"); otherwise low if either mentions "randomised" or "randomized"high · low · insufficient
deviations_from_intended_interventionsNothing: the claim schema has no adherence datainsufficient
missing_outcome_dataAn attrition phrase in evidence_span ("dropout", "dropped out", "attrition", "lost to / loss to follow-up", "withdrew", "discontinued"). A proportion stated nearby ("15%" or "9 of 60") of 20% or more gives high; a lower or unstated one gives some concernshigh · some_concerns · insufficient
measurement_of_outcomeBoth outcome and effect_measure knownlow · insufficient
selection_of_reported_resultNothing: no pre-registration datainsufficient
The 20% cut-off is a rule of thumb. RoB 2 itself sets no attrition threshold, and whether missing data biases a result depends on why it is missing. Treat a drafted high or some-concerns rating as a prompt to read the paper's flow diagram. Matching is still literal wording, so rephrased attrition can be missed.

Newcastle-Ottawa: three star categories

CategoryStars awardedMax
selection1 if any claim has a known population, +1 if any has a known cohort_identity. The other selection items aren't in the schema. 0 stars here means neither is known: not assessable4
comparability2 if any claim names an adjustment_context (confounders adjusted for). 0 if the claims say the analysis was unadjusted ("none", "unadjusted", "crude"). 0 and not assessable if it is unknown2
outcome_exposure1 if outcome and effect_measure are both known. Follow-up length and completeness aren't captured. 0 stars means not assessable3
Missing data is not a zero. Each category carries assessable. A 0 that only means "the claims don't record this" shows as 0/2 ★ (not assessable) and doesn't affect GRADE. Only an assessable 0, such as an analysis the paper itself calls unadjusted, marks the paper high-risk. A human-scored category always counts as assessable.

AMSTAR-2: seven of sixteen items

Each item has two text patterns searched in the claims' evidence_span. A stated shortcoming gives no and is checked first; otherwise a match on the expected signal gives yes; otherwise insufficient_information.

ItemCriticalYes onNo on
protocol_registered_prioryes"PROSPERO", "protocol … registered""no protocol", "not registered", "unregistered"
adequate_literature_searchyes"systematic search", "PRISMA", "search strategy""single database", "no grey literature", "English-language only"
study_selection_duplicateno"independently screened/selected", "duplicate screening""single reviewer screened", "screened by one author"
list_of_excluded_studiesno"excluded studies""no list of excluded", "excluded studies not reported"
risk_of_bias_assessment_included_studiesyes"risk of bias", "quality assessment""risk of bias not assessed", "no quality assessment"
risk_of_bias_accounted_in_resultsyes"risk of bias" near "interpret", "discuss" or "result""did not consider risk of bias"
publication_bias_assessedno"funnel plot", "publication bias", "Egger""publication bias not assessed", "too few studies to assess"

Overall confidence follows the AMSTAR-2 rule:

  • any critical item rated no gives critically low;
  • if a critical item is only insufficient_information, overall confidence is insufficient_information too, and the note names the unconfirmed items;
  • with every critical item confirmed, more than one non-critical no gives low, exactly one gives moderate, none gives high.
Only 7 of the 16 items are checked. Even a draft "high" covers the representative subset in the table, not the full instrument. Critically low marks the paper high-risk for GRADE.

GRADE: one certainty for the set

GRADE (Guyatt et al., BMJ 2008) rates how confident you can be that an effect estimate is close to the true effect. /ref:review gives one rating per batch, not per outcome, so keep a batch to one question.

highVery confident the true effect lies close to the estimate.
moderateThe true effect is likely close, but could be substantially different.
lowLimited confidence; the true effect may be substantially different.
very_lowVery little confidence; the true effect is likely substantially different.

Baseline: high if every active claim in the set comes from an RCT, otherwise low. Then each factor below that downgrades takes the rating down one level, stopping at very_low.

FactorDowngrades whenNot assessed when
risk_of_biasAny paper is high-risk: a RoB 2 domain rated high, an assessable NOS category with 0 stars, or AMSTAR-2 critically lowNo paper has a single real rating
inconsistencyA potential_conflict or contradicts relation (not stale) links the set's papersNo relations touch these papers yet; run /ref:weave
imprecisionNo active claim reports an uncertainty_interval (CI, SE or p-value)No active claims
indirectnessClaims disagree on population, intervention, outcome or comparator (unknowns ignored)No active claims
publication_biasNeverAlways: a curated library has no funnel plot or search-completeness data

Compared with full GRADE, this is deliberately simpler. Each factor moves one level at most (no "very serious" two-level downgrade), there is no upgrading for large effects or dose-response, and indirectness treats any difference in PICO values as a mismatch. The rating is a starting point for your own judgement.

    Reading the result:

    • Baseline low: not every claim is from an RCT.
    • Indirectness: the cohort studies older adults against an inactive comparator, while the trials use healthy adults against stretching. Low minus one is very_low.
    • No risk-of-bias downgrade: the cohort records no adjustment_context, so comparability is 0 stars but not assessable. Had the claim said "none" (an explicitly unadjusted analysis), that 0 would count as high risk and the rating would already be at the floor.
    • AMSTAR-2 stays open: three critical items match, but "risk of bias considered in the results" isn't in the evidence text, so overall confidence is not claimed.
  4. Risk of bias: the cohort records no adjustment_context, so comparability gets 0 stars, which counts as high risk.
  5. Indirectness: the cohort studies older adults against an inactive comparator, while the trials use healthy adults against stretching.

    6. Low minus two is floored at very_low. Meanwhile AMSTAR-2 reads high although risk_of_bias_accounted_in_results, a critical item, is only insufficient.

  6. Review a domain yourself

    Every rating starts as model_draft. Ask Claude to record your own judgement on a domain; it runs verify.py review-appraisal with a decision (accept, edit or reject), a reviewer name and a rationale. An edit also takes the replacement values:

    output from a scratch library

    › verify.py review-appraisal --pmid 99000201 --checklist RoB2 --domain-key deviations_from_intended_interventions --decision edit --reviewer CE --rationale "methods section: per-protocol analysis only, 4 crossovers" --replacement-file edit.json
# edit.json: {"rating": "some_concerns"}
{
  "correction_id": "cor-c55387424ce9",
  "target_type": "appraisal",
  "target_id": "99000201:RoB2:deviations_from_intended_interventions",
  "decision": "edit",
  "replacement_value": { "rating": "some_concerns" },
  "rationale": "methods section: per-protocol analysis only, 4 crossovers",
  "status": "active", …
}
› /ref:review 99000201 99000202 99000203 --batch rct-only --refresh
  "deviations_from_intended_interventions": {
    "rating": "some_concerns", "review_status": "human_edited", "reviewer": "CE",
    "note": "methods section: per-protocol analysis only, 4 crossovers",
    "draft_note": "claim schema does not capture protocol adherence/deviations", … }

    In review.md the row now reads:

    | deviations_from_intended_interventions | some_concerns | — | human_edited (CE) | methods section: per-protocol analysis only, 4 crossovers |

    An edit replaces the machine's note with your rationale, because the old note explained a rating that no longer stands; it is kept as draft_note. An accept or reject keeps the note and appends your rationale. The decision is stored in papers/99000201/corrections.json, so it survives every refresh and applies to any batch that includes the paper. Two things to notice:

    • The certainty stays high. Only a high RoB 2 domain counts as high risk; some_concerns doesn't move GRADE.
    • The all-designs batch from step 3 still shows model_draft for this domain until it is refreshed too.
GRADE itself has no review path. It belongs to the whole set rather than one paper, so it lives only in grade.json. To change it, change its inputs: review domains, fix claims, or resolve conflicts with /ref:weave review, then --refresh.

What gets saved

projects/<slug>/reviews/<batch>/     # or reviews/<batch>/ without --project
  manifest.json             # selector, frozen PMID list, tier report, resolved_at
  appraisals/<pmid>.json    # one checklist result per paper
  grade.json                # baseline, five factors, certainty
  review.md                 # everything above as readable tables, YAML frontmatter

A batch is frozen: running /ref:review --batch <label> again reuses it, even if the selector would now pick different papers. --refresh re-resolves the selector, re-drafts every domain, applies recorded reviews, and reports added_pmids and removed_pmids. The dashboard's Insights → Maturity view shows each batch's certainty; see Evidence insights.

What the drafts cannot tell you

  • Methods quality. Blinding, allocation concealment, protocol deviations, selective reporting and follow-up completeness aren't in the claim schema. Read the methods sections.
  • Absence of a signal. Literal matching only finds wording it expects. insufficient_information means "not found in the claims", never "not done".
  • Most shortcomings. A draft rates high or no only when the evidence text states the problem in words the patterns know (quasi-random allocation, 20%+ attrition, an unregistered protocol). A paper that simply doesn't mention a problem is never rated down for it.
  • Per-outcome certainty. One rating covers the whole batch. Split batches by outcome if the outcomes differ.

Minimal recipes

illustrative output

› /ref:review --project <slug> --screened included --batch <label>   # appraise the included papers
› /ref:review --project <slug> --study <id> --batch <label>         # one study's publications
# then ask Claude to accept / edit / reject a domain (verify.py review-appraisal)
› /ref:review --project <slug> --batch <label> --refresh             # re-draft with reviews applied
› /ref:weave <pmid…>                                                  # add relations so inconsistency can be assessed

Command reference: /ref:review; review decisions use the same corrections.json mechanism as /ref:verify. For screening and the PRISMA flow that usually come before appraisal, see Systematic review.
