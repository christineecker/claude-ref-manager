Tutorial

From claim to concept graph

How one paper becomes claims, how claim text lands on stable concept nodes, and how those nodes get typed edges and a regenerable OKF bundle. Read the diagram first, then follow the commands that drive each step. Everything here is taken from agents/ref-extractor.md and the scripts concept.py, relation.py and okf_emit.py.

The pipeline

Only the extractor is an LLM step, and it can only return JSON. Everything after it is validation, exact matching and deterministic comparison. Teal labels on the diagram name the slash command that drives each step.

Step 1: claims

/ref:extract fans out one ref-extractor subagent per PMID, in parallel. Each gets pmid, title, abstract and full_text (or null for abstract-tier papers), and returns one JSON object: a study type plus one claim per reported finding. The subagent has no access to atomic writes, locks or ID allocation; the calling command validates the schema, assigns stable claim IDs and commits.

GroupFields
PICOpopulation intervention comparator outcome timepoint
Resultdirection effect_value effect_measure uncertainty_interval
Contextstudy_design cohort_identity adjustment_context
Provenancelocator evidence_span (direct quote) evidence_tier (abstract or full)
Unknown means unknown. Any field the text does not support is the literal string "unknown". Keys are never omitted and values never guessed. An empty claims list is a valid answer. For the full claim contract see Extracting claims.

Step 2: map claim text to concepts

Concepts are not extracted by the subagent. It emits free text; the calling command, /ref:weave <pmid>, maps each field to a concept inline, because mapping needs judgment and no subagent exists for it. Before minting anything it must call find_concept(): an exact match on name or alias, case-folded and whitespace-normalized. There is no fuzzy matching. /ref:concept edits the same store by hand.

OutcomeWhat happens
matchadd_alias() records the new surface form with provenance claim:<pmid>:<claim_id> or manual. "MI" and "myocardial infarction" become one node.
no matchcreate_concept() mints a slug ID. It refuses if any concept already matches.
collisionThe alias already resolves to a different concept. add_alias() raises; merging is a human decision.

Rows live in graph/concepts.jsonl:

{"concept_id": "<slug>", "name": "<canonical name>",
 "aliases": ["..."],
 "alias_provenance": {"<alias>": {"source": "claim:<pmid>:<claim_id>", "added_at": "..."}},
 "created_at": "...", "updated_at": "..."}

Step 3: propose relations

Still inside /ref:weave <pmid>, propose_relation() compares two claims already mapped to a concept pair. It is a pure function with no LLM. Only claims from different PMIDs are candidates; a paper's claims are never woven against themselves. Edges go to graph/relations.jsonl with subject_concept_id, object_concept_id, type, supporting_claims, source_version_ids, review_state and stale.

RuleBehaviour
opposite directionOnly increase against decrease counts. Null results against either are inconclusive, not oppositional.
comparable contextComparator, effect measure, timepoint and population must match exactly (case and whitespace normalized). "unknown" on either side is a mismatch, never a pass.
auto-proposed typeOnly potential_conflict.
contradictsRequires a recorded review decision and rationale.
staleSet when a supporting claim is superseded. The concept page shows it until the relation is reconfirmed.
Under-link on purpose. A false "not comparable" is recoverable by a manual relation. A false "these conflict" is not.

To promote or demote an edge yourself, use the review form. contradicts is refused without a non-empty rationale:

illustrative output

› /ref:weave review <relation-id> contradicts --rationale "same comparator, 12-week follow-up in both"

Step 4: the OKF view

okf_emit.py generates okf/ from the JSONL and JSON sources: concepts/<id>.md, papers/<citekey>.md, people/, grants/, index.md and log.md. It is an OKF v0.2 bundle: markdown with YAML frontmatter, type required, cross-links as bundle-relative markdown links. Never hand-edit it. Edit the sources and rerun /ref:weave; unchanged inputs give byte-identical output. Run it with no PMIDs to regenerate the views only.

Step 5: query the graph

The graph is read through five routes. Four are deterministic scripts; only /ref:ask and /ref:brief add an LLM step, and their citations are checked against the evidence they were given.

Ask withQuestion it answersWhat it produces
/ref:weave neighbors <slug>What supports, conflicts with or contradicts this concept?JSON {concept_id, outgoing, incoming}: every relation touching the concept, split by direction, each with its supporting-claim trail. A local scan of relations.jsonl, not the OKF tool.
/ref:gaps <selector>
[--intervention-concept <slug>] [--types …]		Where is the evidence thin or unresolved?Findings grouped by type: single_study_fragile, unresolved_conflicts, co_mentioned_ungrouped, population_outcome_gap. Each cites its claim_id, relation_id or pmid. A gap describes this library's coverage, not the literature.
/ref:hypothesize --concept <slug>Which A-C links are untested, given A-B and B-C edges from different papers?Candidates ranked by count of independent A-B / B-C chains, each with its full evidence chain, plus the exact PubMed query, timestamp and result PMIDs. Zero hits reads "not found by this search", never "novel". A reading list, not validated claims.
/ref:ask <question> [selector]
/ref:brief saves a refreshable answer		What does my library say about this question?An answer, a coverage note and unresolved questions, with a citation check (all_resolved) and an explicit insufficient_coverage report. /ref:ask persists nothing.
OKF MCP tools
okf plugin		What is on this concept's page, and who links to it?Markdown concept pages: aliases, relations with review_state, and a STALE mark when a supporting claim was superseded.

The dashboard reads the same records visually: its Insights tab centres an interactive graph on a paper or concept and lets you review conflicts. See Evidence insights.

Worked examples

One small graph, queried four ways. The concepts are tdcs, working-memory, attention and adhd; the PMIDs 38000101 to 38000103 are placeholders. Outputs labelled scratch library are real runs from the scripts, taken from the Graph discovery tutorial and trimmed with …. The graph they run over:

tdcs --contradicts--> working-memory   # was potential_conflict; 38000101 vs 38000102
tdcs --supports--> attention              # 38000103
attention --supports--> adhd          # 38000102
working-memory --extends--> adhd    # 38000101
# no direct tdcs -> adhd edge

1. What touches this concept?

output from a scratch library (trimmed)

› /ref:weave neighbors working-memory
{
  "concept_id": "working-memory",
  "outgoing": [ { "relation_id": "rel-754640c3886b", "type": "extends", "object_concept_id": "adhd", … } ],
  "incoming": [ { "relation_id": "rel-de5834755e5b", "type": "contradicts", "subject_concept_id": "tdcs", … } ]
}

Read it as: working memory extends ADHD evidence, and tdcs contradicts it. Each row carries its supporting_claims, so the next step is to open those claims, not to trust the edge label.

2. Where is the evidence thin?

output from a scratch library (run before the review)

› /ref:gaps 38000101 38000102 38000103
{
  "gaps": {
    "single_study_fragile": [],
    "unresolved_conflicts": [
      { "gap_type": "unresolved_conflict", "relation_id": "rel-de5834755e5b",
        "type": "potential_conflict", "stale": false,
        "subject_concept_id": "tdcs", "object_concept_id": "working-memory",
        "supporting_claims": [ { "claim_id": "c-0001", "pmid": "38000101" }, { "claim_id": "c-0002", "pmid": "38000102" } ] }
    ],
    "co_mentioned_ungrouped": []
  }
}

One open conflict, with the claim IDs it rests on. The empty lists only mean the scratch library has no extracted claim registries, not that the evidence is robust. Resolve the conflict with /ref:weave review rel-de5834755e5b contradicts --rationale "…".

3. What has nobody tested?

output from a scratch library (trimmed)

› /ref:hypothesize --concept tdcs
# 1. graph traversal, no network
[ { "concept_a": "tdcs", "concept_c": "adhd", "chain_count": 2,
    "chains": [
      { "concept_b": "working-memory", "a_b_type": "contradicts", "b_c_type": "extends", … },
      { "concept_b": "attention", "a_b_type": "supports", "b_c_type": "supports", … } ] } ]
# 2. Claude searches PubMed per candidate; query, time and PMIDs are recorded
  "pubmed_check": { "query": "\"transcranial direct current stimulation\" AND \"attention-deficit/hyperactivity disorder\"", "result_pmids": [] },
  "pubmed_note": "Not found by this search … Not proof of novelty: a different query might find something this one didn't."

adhd is a candidate because two independent two-hop chains reach it and there is no direct edge from tdcs. The empty result_pmids reads "not found by this search". It is a reading list, not a finding.

4. What does the library say?

illustrative output

› /ref:ask "Does tDCS improve working memory in adults with ADHD?" --project tdcs-review
# retrieval report first: truncation and insufficient_coverage stated plainly
# then one synthesis call: answer + coverage note + unresolved questions
# then the citation check: all_resolved true, or the citations that did not resolve

This one needs a subagent, so there is no scratch run to show. Note the answer would have to report the open tdcs vs working-memory conflict from example 2 rather than pick a side.

Minimal recipes

illustrative output

› /ref:extract 99000001 99000002            # claims from two papers
› /ref:weave 99000001 99000002              # map to concepts, propose relations, regenerate okf/
› /ref:weave neighbors <concept-slug>       # what supports / conflicts with / contradicts it
› /ref:weave                                 # no PMIDs: regenerate the derived views only
› /ref:gaps --project <slug>                # fragile claims and open conflicts
› /ref:hypothesize --concept <slug>      # ranked A-C candidates
› /ref:ask "<question>"                     # cited answer from the library
