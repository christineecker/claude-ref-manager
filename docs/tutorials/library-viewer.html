Tutorial

Library viewer

/ref:list, /ref:dashboard, and /ref:lint --diff — filter, browse, read PDFs, and track maintenance trend without leaving the library. All three are read-only except the dashboard's notes composer.

Three tools, one inventory

/ref:list — filter, then pipe

No filters at all lists every paper. Combine filters freely; a combination matching nothing prints an explicit "no papers matched" line, never silence.

illustrative output

› /ref:list --source abstract-only,oa-pending --stale-days 180 --sort checked
pmid       title                                  year  source        checked
40665956   Sham tDCS and social cognition in...  2024  abstract-only  2026-02-11
40691132   ...                                                          2026-01-30

The most useful move is --format pmids: no other output, just a bare space-separated PMID list, meant to be piped straight into the repair step.

illustrative output

› /ref:list --issue abstract_only --format pmids
40665956 40691132 40701004
› /ref:fetch 40665956 40691132 40701004
FlagFilters on
--source <badge,...>pdf-backed, full-text, oa-pending, abstract-only, metadata-only
--has / --missing <key,...>ANDed presence check: pdf, fulltext, claims, figures, notes
--tier <abstract|full|unavailable>meta.json.extraction_tier
--year <YYYY|YYYY..YYYY> · --journal <substr>publication year / journal name substring
--retractedretraction_status is retracted or erratum
--issue <lint-bucket>same buckets /ref:lint reports — the direct bridge between the two tools
--project / --reading-status / --query / --from-filethe shared selector grammar used by every other scoped command

For a shape overview rather than a filtered list, --matrix prints a paper × {meta, abstract, fulltext, pdf, figures, claims, indexed, retraction} coverage grid.

/ref:dashboard — browse and read

Default is serve: a local HTTP server on 127.0.0.1, bound to a random per-run token checked against every request's Host/Origin — not reachable from another machine or another browser tab without that token in the URL. It blocks until you stop it with Ctrl-C.

illustrative output

› /ref:dashboard --open
dashboard serving: http://127.0.0.1:53211/?token=9f2c...  (Ctrl-C to stop)

Tabs: Summary, Papers (searchable/sortable table plus the coverage matrix), Coverage, Projects (per-project reading progress), Maintenance (lint trend sparklines). Selecting rows in the Papers tab builds ready-to-copy /ref:fetch / /ref:extract commands for whatever still needs them — the same triage /ref:list --issue gives you, just clickable. The paper panel opens PDFs in-page through a vendored pdf.js (thumbnails, zoom, fit-width, find-in-PDF) and its notes composer saves straight to notes.md through the same path /ref:note uses.

Pass --static (or the literal word build) for a self-contained snapshot instead — good for handing someone a library state without running a server:

illustrative output

› /ref:dashboard --static --open
dashboard built: /Users/you/refs/reports/dashboard/index.html
In static mode the PDF opens in a new browser tab, not in-page, and the notes composer only writes a browser-local draft with a "Copy /ref:note" button — nothing is committed until you actually run /ref:note. A rebuild replaces the whole reports/dashboard/ directory in one step; a failed build never touches the previous snapshot.

/ref:lint --diff — track the trend, not just the snapshot

Plain /ref:lint is a point-in-time report. --snapshot also writes it to maintenance/<UTC-timestamp>.json; --diff [snapshot] compares the current run against a prior one (the most recent, if you don't name one) and reports per-bucket added/removed PMIDs — what got worse and what a repair pass actually fixed.

illustrative output

› /ref:lint --snapshot
# ... report ..., then writes maintenance/2026-08-01T09-00-00Z.json
› /ref:repair-fulltext --limit 20
› /ref:lint --diff
issues:
- abstract_only: 15 (-3) [-40665956, -40691132, -40701004]
- missing_claim_registry: 11 (unchanged)
Errors loudly if no snapshot exists yet, or a named one isn't found — it never silently diffs against nothing.

Putting it together

› /ref:lint --snapshot            # baseline before a repair pass
› /ref:list --issue abstract_only --format pmids
› /ref:repair-fulltext --limit 20       # or /ref:fetch <pmid...> on that list
› /ref:lint --diff                # confirm the buckets actually shrank
› /ref:dashboard --open            # browse what's left, read PDFs, leave notes

/ref:list and /ref:dashboard are read-only reporting layers over the same inventory the maintenance loop repairs — reach for this tutorial when you want to look before (or instead of) running /ref:maintain.
